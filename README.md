#cargos

### Desenvolvedor(a)

Transforma ideias e designs em sites e sistemas que funcionam, escrevendo e mantendo o código da aplicação.

### Product Owner (PO)

É a pessoa responsável por orientar as prioridades do produto. Define o que precisa ser feito e mantém o foco nas entregas que geram valor para os usuários e para o negócio.

### Scrum Master

Facilita o trabalho da equipe e ajuda o time a aplicar o Scrum. Apoia a melhoria das rotinas e a remoção de obstáculos que prejudicam as entregas, articulando ajuda quando necessário.

### Tech Lead

É a referência técnica da equipe. Orienta decisões de arquitetura e código, apoia os desenvolvedores e ajuda a resolver problemas mais complexos.

### UI (User Interface): interface do usuário

É a área de design voltada à interface. Trabalha cores, tipografia, botões, ícones e organização visual para criar telas claras, consistentes e atraentes.

### UX (User Experience): experiência do usuário

É a área voltada à experiência de uso. Busca tornar o site ou aplicativo útil, intuitivo e agradável, ajudando as pessoas a concluir suas tarefas.

### Designer UX/UI

Reúne atividades de experiência do usuário e design de interface. Pensa tanto na facilidade de uso quanto na apresentação visual das telas.

### Desenvolvedor(a) back-end

Cuida dos bastidores do sistema: regras de negócio, acesso ao banco de dados, autenticação, permissões e comunicação com outros serviços.

### UX Research: pesquisa com usuários

Investiga necessidades, dificuldades e hábitos das pessoas por meio de entrevistas, observação e outros métodos de pesquisa. Traz evidências para orientar decisões antes e durante o desenvolvimento.

## Como distribuir os papéis em um projeto de turma

As sugestões abaixo ajudam a dividir as responsabilidades conforme os interesses e as habilidades dos alunos. Uma pessoa pode assumir mais de um papel, desde que a carga de trabalho seja viável e as responsabilidades estejam claras.

### 1. Product Owner (PO) / UX Research

**Quem escolher:** alguém comunicativo e organizado, que tenha visão do projeto como um todo e goste de entender o problema e orientar a ideia do produto.

**O que faz no projeto:**

- Define o problema e o objetivo do sistema com base na planilha de temas.
- Escreve histórias de usuário, que descrevem uma necessidade do ponto de vista de quem utilizará o sistema.
- Realiza pesquisas de campo ou entrevistas rápidas com o público-alvo.
- Ajuda a equipe a manter o foco no escopo principal, isto é, no que foi combinado para a entrega.

**Exemplo de história de usuário:**

> Como jovem em busca de emprego, quero cadastrar meu currículo para me candidatar a uma vaga.

### 2. Designer UX/UI

**Quem escolher:** alguém com interesse em design, que goste de trabalhar no Figma, organizar cores, tipografia e espaçamentos e pensar na facilidade de uso das telas.

**O que faz no projeto:**

- Cria o protótipo navegável no Figma para computador e celular.
- Define a paleta de cores, os botões, os ícones e a tipografia.
- Entrega o layout com medidas, cores, fontes e orientações para a implementação pelo time de front-end.

### 3. Desenvolvedor(a) front-end (HTML, CSS e JavaScript)

**Quem escolher:** alunos que gostem de construir a parte visual no navegador, organizar elementos com Flexbox, estilizar botões e criar interações.

**O que fazem no projeto:**

- Transformam o design do Figma em código organizado com HTML, CSS e JavaScript.
- Adaptam as telas para funcionar em celulares e computadores, usando um layout responsivo.
- Implementam validações de formulário, como avisar quando o campo de e-mail estiver vazio.
- Conectam as telas à API do back-end, a interface que permite trocar dados com o servidor.

### 4. Desenvolvedor(a) back-end / Banco de dados

**Quem escolher:** alunos que gostem de lógica, regras de negócio e organização de dados e tenham interesse na estrutura que sustenta o funcionamento das telas.

**O que fazem no projeto:**

- Estruturam o banco de dados, incluindo tabelas de usuários, cadastros e solicitações.
- Desenvolvem a lógica da aplicação e as rotas da API para cadastrar, listar, editar e excluir dados.
- Validam no servidor as informações recebidas dos formulários e controlam as permissões de acesso.
- Implementam o armazenamento seguro dos dados no banco.

### 5. Tech Lead / Scrum Master (papéis acumulados)

**Quem escolher:** alguém com maior familiaridade técnica, que saiba usar Git e GitHub, consiga ajudar a resolver conflitos de código e goste de apoiar os colegas quando surgirem dificuldades.

**O que faz no projeto:**

> O conteúdo original foi interrompido neste ponto. As atividades deste item ficaram pendentes de envio.

**Observação:** Tech Lead e Scrum Master têm responsabilidades distintas. Neste projeto de turma, a proposta é que uma pessoa acumule os dois papéis.
